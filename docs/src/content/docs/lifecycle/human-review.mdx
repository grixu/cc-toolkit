## Why this stage

By now the change is reviewed and tested, and the one thing left is a person's approval.
This stage makes that approval cheap: proof the change works before the reviewer opens it, a pull request they can read in one screen with a risk label that says how closely to look, and an agent that answers their comments and keeps CI green until they approve.

## What to run

<StageCommands stage="human" />

The order matters: record the proof with [pr-proof](/plugins/pr-proof/) first, open the pull request with [`/dev-kit:pr-open`](/plugins/dev-kit/pr-open/) so the proof goes into it, then let [`/dev-kit:pr-shepherd`](/plugins/dev-kit/pr-shepherd/) drive it.
You rarely run [`/dev-kit:ci-fix`](/plugins/dev-kit/ci-fix/) by hand: pr-shepherd calls it when a check fails.

## What arrives and what leaves

- **Arrives:** a reviewed and tested branch.
- **Leaves:** an approved pull request with green checks, ready to merge.
