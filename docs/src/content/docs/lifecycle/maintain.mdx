Maintain sits outside the [ADLC](/lifecycle/) cycle and feeds it.
It covers the work that doesn't follow a merge: dependency upgrades, and the rules that keep the agent from repeating a mistake.

## What goes wrong without it

A correction you type in chat is gone when the session ends, so the next session makes the same mistake.
A dependency upgrade arrives when its maintainers release it, and a green CI run doesn't tell you whether its changes reach your code.
Neither waits for a stage of the cycle, so these plugins run whenever the need comes up.

## Who does what

- **The agent** finds the corrections in a session and proposes a rule for each, or maps every change in an upgrade to where your code uses the package.
- **You** accept, change or skip each proposed rule, and decide whether to take an upgrade.

## Turn corrections into rules

Two plugins write rules, and the rules work in the other stages:

- [`/session-learner:learn`](/plugins/session-learner/) reads the current session, finds the moments you corrected the agent, and proposes a change to `.claude/rules/`, `CLAUDE.md` or a hookify rule for each one. It shows one finding at a time and writes only what you accept.
- [`/hookify:hookify`](/plugins/hookify/hookify/) writes a hookify rule from your description, or from the mistakes in the current conversation.

The rules come back in the cycle:

- Every session reads `CLAUDE.md` and the rules files, so every stage starts with them.
- In [Build](/lifecycle/build/), hookify rules warn about or block an edit that breaks them.
- In [Self-review](/lifecycle/self-review/), code-review reads your rules as conventions and holds the change to them.

Run session-learner before `/compact` or `/clear`: it reads only the conversation still in context.

## Check an upgrade before it breaks you

[`/dev-kit:dep-upgrade-check`](/plugins/dev-kit/dep-upgrade-check/) takes a package and a target version, or a Renovate or Dependabot pull request.
It checks the target's security record, lists every change up to the target, and marks each one as affecting your code or not.
It ends with a `safe`, `safe with changes` or `breaking` verdict and the evidence behind it.

## What arrives and what leaves

- **Arrives:** a session in which you corrected the agent, or a dependency and a target version.
- **Leaves:** rules that the next session follows, or a verdict on the upgrade with evidence.
