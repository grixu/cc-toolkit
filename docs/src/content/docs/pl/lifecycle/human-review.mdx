## Po co ten etap

Na tym etapie zmiana jest już przejrzana i przetestowana; brakuje tylko akceptacji człowieka.
Ten etap sprawia, że ta akceptacja jest tania: dowód, że zmiana działa, zanim reviewer ją otworzy, pull request do przeczytania na jednym ekranie z etykietą ryzyka, która mówi, jak uważnie patrzeć, i agent, który odpowiada na komentarze i trzyma CI na zielono do akceptacji.

## Co uruchomić

<StageCommands stage="human" />

Udowodnij zmianę z [pr-proof](/pl/plugins/pr-proof/), otwórz pull request z [`/dev-kit:pr-open`](/pl/plugins/dev-kit/pr-open/), a potem oddaj go [`/dev-kit:pr-shepherd`](/pl/plugins/dev-kit/pr-shepherd/).
pr-proof dołącza wideo do pull requesta, który już istnieje; jeśli go jeszcze nie ma, zostawia wideo w `~/Downloads/` do ręcznego dołączenia.
[`/dev-kit:ci-fix`](/pl/plugins/dev-kit/ci-fix/) rzadko uruchamiasz ręcznie: pr-shepherd woła go, gdy któryś check padnie.

## Co wchodzi, a co wychodzi

- **Wchodzi:** przejrzany i przetestowany branch.
- **Wychodzi:** zaakceptowany pull request z zielonymi checkami, gotowy do merge'a.
