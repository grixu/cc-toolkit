Reguła działa tylko przy wywołaniach narzędzi po jej utworzeniu.
`/hookify:review-changes` sprawdza zmiany, które już są na branchu albo w drzewie roboczym, więc znajdziesz to, co nowa reguła by wyłapała.
Ocenia wyłącznie według twoich reguł: nie dodaje ogólnych uwag z code review i niczego nie edytuje.

## Uruchomienie

Uruchom komendę na branchu ze zmianami:

<Strip cmd="/hookify:review-changes" />

Uruchamiają ją też prośby w rodzaju „review my changes against hookify rules” albo „check hookify compliance”.

## Co przegląda

Bierze pod uwagę dwa rodzaje zmian:

- **Zacommitowane:** `HEAD` względem brancha bazowego. Baza to merge base z twoim branchem upstream, a dalej z `origin/main`, `origin/master`, `main` albo `master`, zależnie od tego, który istnieje pierwszy.
- **Niezacommitowane:** drzewo robocze i indeks względem `HEAD`, łącznie z nieśledzonymi plikami, których git nie ignoruje.

Gdy są oba rodzaje, prosi o wybór: tylko niezacommitowane, tylko zacommitowane albo oba.
Gdy jest tylko jeden, bierze ten.
Gdy nie znajdzie brancha bazowego, proponuje przegląd samych niezacommitowanych zmian.
Gdy nie ma żadnych zmian, mówi o tym i kończy.

Sprawdza tylko włączone reguły z `event: file` albo `event: all`.
Reguły `bash`, `prompt` i `stop` nie mogą zadziałać na diffie, więc je pomija.
Jeśli żadna z twoich reguł się nie kwalifikuje, kończy i proponuje utworzenie reguły przez `/hookify:hookify`.
Reguła z warunkiem na `file_path` dotyczy tylko pasujących plików.
Pliki usunięte, binarne oraz generowane i lockfile, takie jak `pnpm-lock.yaml` albo `dist/**`, są pomijane, chyba że reguła wskazuje je ścieżką.

Liczą się tylko dodane linie.
Naruszenie w linii kontekstu albo w usuniętej linii nie trafia do raportu.

## Jak czytać raport

Raport najpierw wypisuje reguły z naruszeniami, od tej z największą liczbą, a potem reguły bez naruszeń.
Każde naruszenie podaje plik i linię, wyjaśnia, dlaczego łamie regułę, i cytuje kod:

````markdown
## ⚠️  Rule: `warn-console-log` (warn)

> _🔍 **Console.log detected**_

**Source:** `/home/you/app/.claude/hookify.warn-console-log.local.md`

### Violations

- `src/api/users.ts:42` — _Adds console.log to production source._
  ```
  console.log(user)
  ```
````

Listing 1. Jedna reguła w raporcie

Reguły z `action: block` dostają znacznik 🛑 zamiast ⚠️.
Na końcu raport wypisuje przejrzane i pominięte pliki, z powodem dla każdego pominiętego.
Jeśli subagent zwróci coś nieczytelnego, raport mówi o tym w sekcji „Subagent failures” zamiast ponawiać próbę.

## Po raporcie

Claude pyta, co dalej:

- **Save report to file** zapisuje raport do `.claude/hookify-review-<YYYY-MM-DD>-<HHMM>.md`, z dopiskiem `-2`, `-3` i tak dalej, gdy nazwa jest zajęta.
- **Enter Plan Mode for fixes** otwiera Plan Mode z planem poprawek pogrupowanym według plików, bo poprawia się pliki, a nie reguły.
- **Done** kończy przegląd.

:::note
Przegląd nigdy nie edytuje twojego kodu ani reguł. Poprawki zaczynają się dopiero po akceptacji planu w Plan Mode.
:::
