A diff shows what changed, file by file, in alphabetical order.
It doesn't show which change explains the others, or why the author made it.
code-story turns the change into a **code story**: a chaptered page for a reader who has never seen the codebase.
The change is re-cut into the steps it could have been reviewed in.
Each chapter answers one question with the lines it is about, and notes are pinned to those lines.

## Where it works

<LifeMap focus="code-story" animate={false} />

code-story is a supporting plugin in [03c Human review](/lifecycle/human-review/).
There, [`/dev-kit:pr-open`](/plugins/dev-kit/pr-open/) orchestrates the pull request.
It asks for a story in a background subagent and adds a `## Code story` section with the link to the pull request description.
code-story writes its own prose through [anti-slop](/plugins/anti-slop/) before it assembles the page.

You can also run it on its own, on any branch or pull request.

## When to reach for one

- A reviewer is new to the part of the codebase the change touches.
- The change is large, and its files only make sense in a certain order.
- You want to explain a stack of pull requests as one change.
- You come back to a change later and want to know why the code took this shape.

Every claim in a story rests on something the skill read: the diff, a commit, the pull request, a review, a ticket, a spec, or the code.
When the reason for a change is nowhere to be found, the story says so instead of inventing one.

## Install

Installing code-story also installs [anti-slop](/plugins/anti-slop/), which cleans the prose of every chapter before the page is assembled.

:::caution[An older personal skill]
If you used `code-story` as a personal skill before, delete `~/.claude/skills/code-story` after installing.
Otherwise two skills with the same name compete.
:::

## Requirements

- Node.js 22 or later, for the scripts that assemble and check the page.
- `git`, and the GitHub CLI `gh` logged in, to find the base, the pull request and its stack.
- The Artifact tool (claude.ai), to publish the story. Without it, the story opens as a local HTML file.
- Claude Code 2.1.271 or later, which the option pickers in the settings need.

## Run it

<Strip cmd="/code-story:code-story" />

With no arguments, the skill tells the story of the current branch.
It measures the branch against the base of its open pull request, the nearest stacked pull request, or the default branch.
[`/code-story:code-story`](/plugins/code-story/code-story/) covers the arguments, the steps of a run, and what the page contains.

## Settings

Set them in `/plugin` → code-story → configure.
The plugin's mod hands them to the skill through its `config` tool.

| Setting | Default | What it does |
|---|---|---|
| `second_language` | empty | A language tag, such as `pl`. Empty means English only. Code names and programming terms stay in English in every language. |
| `gloss_first_use` | `true` | In the second language, an English term's first use gets its translation in parentheses. |
| `diagram_skill` | empty | An installed diagram skill, such as `fireworks-tech-graph`. Empty means the built-in diagrams. |
| `uncommitted` | `ignore` | `ignore` tells the committed change without asking. `include` adds uncommitted changes without asking. `ask` asks each time. |
| `stack` | `ask` | For a branch in a stack of open pull requests: `ask` whether to tell the whole stack, `always`, or `never`. |

Table 1. code-story settings.

An invalid value falls back to the default, and the skill repeats the warning in its report.
Without the `config` tool, the skill uses the defaults and says so.

A request overrides a setting for one run:

- "po polsku" or "in German" sets the second language.
- `stack` and `no stack` answer the stack question.
- `uncommitted` includes uncommitted changes.

When nobody can answer a question, as in a subagent, an `ask` setting takes its safe answer: this branch only, and uncommitted changes left out.
Untracked files are never part of a story.

## Updates under the same link

A story describes one branch, or one stack, and stays at one link.
When you run the skill again, it looks for an existing story in this order:

1. A story link in your request.
2. A story it published earlier in the same conversation for this branch.
3. A `## Code story` section with a `claude.ai` link in the pull request description.

The page records its repository, branch, base, and head commit.
When the repository and branch match, the skill updates the story instead of starting over.
It rewrites the chapters whose code changed, adds chapters for new mechanisms, and drops chapters for removed ones.
It then publishes a new version under the same link.

After a rebase or a force-push, the old head commit is no longer in the branch's history.
The skill then reads the whole change again, and still publishes under the same link.

It doesn't search your Artifact gallery for a story.
Without one of the three sources above, it starts a new story.

## Stories of pull request stacks

Your branch can sit in a stack: its pull request targets another open pull request's branch, or another pull request targets yours.
The skill follows the chain of open pull requests down and up from your branch.
A chain of two or more is a stack.

With the `stack` setting at `always`, or `stack` in the request, one story covers the whole stack.
It runs from the bottom pull request's base to the top pull request's head, and the report names the pull requests it covers.
With `never`, or `no stack`, it covers only your branch.

The skill ignores pull requests from forks and branch names with unusual characters, and names any that it dropped in its report.

## Who can see the story

A new story is a private Artifact on claude.ai.
Only you can open it until you share it.
Share it on claude.ai before its link goes into a pull request, or reviewers can't open it.
pr-open reminds you of this when it adds a new story's link.

The page quotes lines of your code and carries the repository name, branch, base, and head commit.
Anyone you share it with sees those.
