A rule only fires on the tool calls made after you write it.
`/hookify:review-changes` checks the changes already on your branch or in your working tree, so you find what a new rule would have caught.
It reviews only against your rules: it adds no general code review comments and edits nothing.

## Run it

Run the command on a branch with changes:

<Strip cmd="/hookify:review-changes" />

Phrases such as "review my changes against hookify rules" or "check hookify compliance" also start it.

## What it reviews

It looks at two kinds of changes:

- **Committed:** `HEAD` against the base branch. The base is the merge base with your upstream branch, then `origin/main`, `origin/master`, `main`, or `master`, whichever exists first.
- **Uncommitted:** the working tree and the index against `HEAD`, including untracked files that git doesn't ignore.

When both exist, it asks you to pick uncommitted only, committed only, or both.
When only one exists, it uses that one.
When it can't find a base branch, it offers to review the uncommitted changes only.
When there are no changes at all, it says so and stops.

It checks only enabled rules with `event: file` or `event: all`.
`bash`, `prompt`, and `stop` rules can't fire on a diff, so it skips them.
If none of your rules qualify, it stops and suggests creating one with `/hookify:hookify`.
A rule with a `file_path` condition applies only to the files that match it.
Deleted files, binary files, and generated or lock files such as `pnpm-lock.yaml` or `dist/**` are left out, unless a rule targets them by path.

Only added lines count.
A violation on a context line or a removed line isn't reported.

## Read the report

The report lists rules with violations first, the most violations at the top, then the rules with none.
Each violation names the file and line, says why it breaks the rule, and quotes the code:

````markdown
## ⚠️  Rule: `warn-console-log` (warn)

> _🔍 **Console.log detected**_

**Source:** `/home/you/app/.claude/hookify.warn-console-log.local.md`

### Violations

- `src/api/users.ts:42` — _Adds console.log to production source._
  ```
  console.log(user)
  ```
````

Listing 1. One rule in a report

Rules with `action: block` get a 🛑 marker instead of ⚠️.
At the end, the report lists the files it reviewed and the files it skipped, with a reason for each.
If a subagent returns something it can't read, the report says so under "Subagent failures" instead of retrying.

## After the report

Claude asks what to do next:

- **Save report to file** writes the report to `.claude/hookify-review-<YYYY-MM-DD>-<HHMM>.md`, with `-2`, `-3`, and so on when the name is taken.
- **Enter Plan Mode for fixes** opens Plan Mode with a fix plan grouped by file, because you fix files, not rules.
- **Done** ends the review.

:::note
The review never edits your code or your rules. Fixes start only when you approve the plan in Plan Mode.
:::
