# cc-toolkit logo

The logo is four upright plates in isometric projection. The three plates at the back are neutral stone, and the front one is bottle green. Each plate stands for a tool in the toolkit, and the green one is the tool you are using now. The construction follows grixu.dev's mark: a true 30° isometric projection, flat faces shaded by lightness alone with the light from the upper left, and exactly one accent object. It shares no shapes or colours with the grixu.dev cube.

All assets live in `brand/logo/` and are generated by `brand/logo/src/build.py`. Edit the script and rebuild, never the output files:

```sh
uv run --with fonttools python3 brand/logo/src/build.py
```

The build needs Google Chrome and ImageMagick (`magick`), because it rasterises the PNG and ICO files with headless Chrome.

| --- | --- |

| `svg/mark-mono-ink.svg`, `svg/mark-mono-white.svg`, `svg/lockup-mono-*.svg` | One colour: print, embossing, stamps, laser cutting, single-colour merch |

All SVGs are transparent, and their text is converted to outlines, so they do not depend on installed fonts. `on-dark` and `on-light` name the ground the file is coloured for, not the file's own background.

## Colour: bottle green

Every ramp keeps one hue, the three faces differ only in lightness, and chroma is a fixed fraction of the sRGB ceiling for each lightness. The paper version has its own remapped ramps rather than the dark version recoloured. The hex values are the sRGB conversions that every asset uses.

| | On dark | On light |
| --- | --- | --- |
| Ground | `oklch(0.17 0.015 160)` `#0A110D` | `oklch(0.965 0.008 120)` `#F3F4EE` |
| Stone, top | `oklch(0.76 0.024 140)` `#A9B5A7` | `oklch(0.84 0.027 140)` `#C2CFBF` |
| Stone, left | `oklch(0.6 0.019 140)` `#7A8378` | `oklch(0.66 0.021 140)` `#8C9689` |
| Stone, right | `oklch(0.46 0.015 140)` `#545A52` | `oklch(0.5 0.016 140)` `#5F665D` |
| Green, top | `oklch(0.8 0.115 158)` `#79D4A1` | `oklch(0.5 0.078 160)` `#367154` |
| Green, left | `oklch(0.68 0.098 158)` `#60AB81` | `oklch(0.4 0.063 160)` `#25523C` |
| Green, right | `oklch(0.56 0.081 158)` `#488362` | `oklch(0.31 0.049 160)` `#173828` |
| Wordmark | `oklch(0.93 0.008 140)` `#E5E9E4` | `oklch(0.24 0.012 150)` `#1B211C` |
| Secondary text | `oklch(0.68 0.012 140)` `#949A93` | `oklch(0.46 0.012 150)` `#545A54` |

On dark, the stone steps down in lightness and the green steps up, so the front plate stands out by lightness and not by hue alone. The green is deliberately quieter than grixu.dev's phosphor green, so it reads as a relative of the parent brand and not a copy.

Only two things are green: the front plate and the hyphen in `cc-toolkit`. Do not colour other plates, the rest of the wordmark or the taglines green.

## Wordmark

The wordmark is `cc-toolkit`, lowercase, set in Chakra Petch SemiBold and converted to outlines. Chakra Petch is licensed under the OFL and lives in `brand/fonts/` with its licence. Taglines on the social images use Chakra Petch Regular.

Always use the SVG. Do not type `cc-toolkit` in a font as a stand-in for the logo, and do not set it in capitals or title case.

Proportions are measured against the mark's height:

- **Horizontal lockup:** the wordmark's x-height is 0.33 of the mark's height, the gap between them is 0.28, and the wordmark is centred vertically on its x-height, not on its ascenders.
- **Vertical lockup:** the x-height is 0.22 of the mark's height, and the baseline sits 1.2 mark heights plus 0.75 type sizes below the top. Both parts are centred horizontally.

## Clear space and minimum sizes

Keep clear space around the logo equal to half the mark's height on every side.

| Asset | Minimum |
| --- | --- |
| Horizontal lockup | 24 px mark height (about 100 px wide) |
| Vertical lockup | 80 px wide |
| Mark alone | 20 px; below that use the favicon files, which sit on a tile |

Below 24 px the wordmark stops reading, so show the mark alone with the name beside it as live text.

## Do not

- Recolour the plates, add gradients, glows, outlines or drop shadows.
- Rotate, mirror or re-project the mark. The light always comes from the upper left.
- Change the number of plates or move the green one away from the front.
- Put the on-dark version on a light ground, or the reverse. Use the matching file.
- Place the logo on a busy photo without a ground: use the dark ground as a bar or tile behind it.

## Icons

| File | Size | Where |
| --- | --- | --- |
| `icons/favicon.svg` | vector | Modern browsers. Transparent, and follows `prefers-color-scheme`: the light ramps on light tabs, the dark ramps on dark tabs |
| `icons/favicon.ico` | 16, 32, 48 | Legacy browsers and RSS readers |
| `icons/favicon-16/32/48.png` | as named | Raster favicons |
| `icons/apple-touch-icon.png` | 180 | iOS home screen |
| `icons/icon-192.png`, `icons/icon-512.png` | as named | Web app manifest. The mark fills 62% of the tile |
| `icons/icon-maskable-512.png` | 512 | Manifest `"purpose": "maskable"`. The mark fills 50%, inside the round safe zone |
| `icons/icon.svg`, `icons/icon-maskable.svg` | vector | Sources of the tiles, for stores and tools that take SVG |

The ICO and PNG favicons sit on a dark rounded tile. A raster cannot follow the colour scheme the way `favicon.svg` does, and no transparent version keeps the green plate visible on both light and dark tabs.

```html
<link rel="icon" href="/favicon.ico" sizes="32x32">
<link rel="icon" href="/favicon.svg" type="image/svg+xml">
<link rel="apple-touch-icon" href="/apple-touch-icon.png">
<link rel="manifest" href="/manifest.webmanifest">
```

The `sizes="32x32"` on the ICO is deliberate: without it, Chrome prefers the ICO over the SVG.
